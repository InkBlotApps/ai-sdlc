Execution architecture

Deployment

Deployment philosophy

Use the least-complex execution model that works

Do not deploy an autonomous service when a versioned artifact, skill, or workflow is enough. Capabilities should earn their way into more expensive and complex runtime models.

D0Artifact / schema / policy
D1Skill / prompt / agent definition
D2CI/CD or deterministic workflow
D3Serverless / durable agent workflow
D4Ephemeral autonomous container
D5Managed hosted agent
D6Dedicated agent/application service
D7Local/private LLM infrastructure

Shearing layers

Fast layers learn. Slow layers remember.

Different parts of the system should change at different rates. Successful experiments are promoted inward toward slower, more durable layers only after they prove useful.

Fast — Experimentprompts, local guidance, temporary agent instructions
Fast–Adaptive — Learnskills, eval definitions, agent definitions, policy mappings
Adaptive — OperationalizeCI/CD, durable workflows, orchestration
Moderate — ProductizeAPIs, collectors, workers, app services
Slow — StandardizeBinder schemas, IDs, control/evidence models, taxonomy contracts
Slowest — Anchoridentity, network boundaries, durable stores, regulatory constraints
Experiment→Observe→Validate→Repeat→Promote→Standardize

Skills first

Use skills when specialized knowledge and tools are needed but persistent state and autonomous runtime are not.

CI/CD before services

Repository governance naturally belongs where commit, actor, branch, build, artifact, and status are already known.

Durable workflow for waiting

Use workflow state for timers, approvals, retries, callbacks, escalation, and human-in-the-loop. Do not leave a container running for three days.

Ephemeral autonomy

Autonomous repository analysis belongs in disposable containers with scoped identity, explicit tools, network controls, resource limits, and complete evidence.

Local models are an option

Use private/local inference for sovereignty, offline operation, sensitive boundaries, specialized models, or measured economics—not because “local must be cheaper.”

Separate control and execution

Governance policy should remain independent of the workers, runtimes, clouds, and model providers that execute it.
